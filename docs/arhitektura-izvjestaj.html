Home OS: zašto je kod posložen ovako

Home OS nije obična CRUD aplikacija nego platforma. Zadatak izričito traži da se nove aplikacije dodaju kao punopravni dio sistema — bez diranja postojećeg koda. Cijela struktura izvire iz tog jednog zahtjeva.

Backend · .NET 8 / C# Frontend · React 19 + TypeScript Obrazac · Modularni monolit + vertical slices

01 Glavni razlog

Jedna odluka objašnjava sve ostalo: sistem mora biti otvoren za proširenje, a zatvoren za izmjenu.

U zadatku se traži 8 ugrađenih aplikacija (Dashboard, Tasks, Kanban, Calendar, Reminders, Notes, Finance, Life admin) koje se ponašaju kao dodaci na zajedničku osnovu. Ako svaka nova aplikacija zahtijeva prepravku postojećih, sistem se ne skalira i svaka izmjena nosi rizik. Zato je kod podijeljen tako da je svaka aplikacija samostalan modul koji se "ukopča" u zajedničku platformu (kernel).

„Moduli se ne poznaju međusobno. Kad dodam novu aplikaciju, ne diram nijedan postojeći modul — samo napišem novi HomeOs.Modules.X i on se sam registruje u platformu preko manifesta i event busa."

Vertikalni slojevi unutar modula

Umjesto klasične podjele po tehničkim slojevima (svi kontroleri na jednom mjestu, svi servisi na drugom), svaka funkcionalnost je zaokružena cjelina: domenski model, endpointi i pristup bazi stoje zajedno. Kad radiš na jednoj funkciji, sve ti je u istom modulu — lakše se čita, lakše testira, manje sudaranja pri radu više ljudi.

FinanceModule.cs ★
Najvažniji fajl: ovdje se modul ukopčava u platformu — registruje bazu, event handlere, priključke i svoj manifest. Vidi ispod.

U FinanceModule.cs se vidi cijela filozofija — modul sam sebe prijavi platformi kroz standardne priključke, a host ga automatski pokupi:

// Composition za Finance app — host ga registruje isto kao bilo koju drugu app.
public static IServiceCollection AddFinanceModule(...) {
    services.AddDbContextPool<FinanceDbContext>(...);   // vlastita baza
    services.AddEventHandlers(...);                    // sluša event bus
    services.AddScoped<ICalendarSource, BillsCalendarSource>();  // → kalendar
    services.AddScoped<ISearchProvider, FinanceSearchProvider>(); // → pretraga
    services.AddHostedService<BillDispatcher>();        // → podsjetnici
    services.AddSingleton<IAppModule, FinanceAppModule>(); // → najavi app
}

// Manifest: ime, ikona, boja, rute, dozvole — platforma iz ovoga gradi nav i pristup.
new AppManifest("finance", "nav.finance", ..., "/finance", "/api/finance",
                ["read:finance", "write:finance"]);

05 Kako je backend organizovan

Čest pitanje: „ima li servisni sloj?" — Nema klasičnog. I to je namjerna odluka.

Backend ne koristi teški Service / Repository sloj kroz koji sve prolazi. Umjesto toga koristi Minimal APIs + vertical slice: svaka ruta je jedna funkcija (handler), a sve što joj treba ubaci se kroz parametre (dependency injection). Otvoriš handler i vidiš cijelu radnju od početka do kraja — validacija → baza → odgovor — bez skakanja kroz tri sloja.

// Ruta = jedna funkcija. Zavisnosti dolaze kroz parametre (DI).
private static async Task<IResult> ListBudgetsAsync(
    ICurrentMember me,      // ko je ulogovan  (platformski servis)
    FinanceDbContext db,    // baza modula     (EF Core, direktno)
    CancellationToken ct) {
    // ... EF Core upit direktno, bez repository omotača:
    var budgets = await db.Budgets.Where(b => b.HouseholdId == me.HouseholdId)...
}

„Ne koristimo teški servisni sloj jer bi za ovakve module bio suvišan boilerplate. Svaka ruta je samostalan slice — logika je na jednom mjestu i čita se odozgo. Zajedničke stvari (korisnik, prevodi, novac, događaji) su apstrahovane kao platformski servisi i ubacuju se kroz dependency injection. Najmanje koda uz jasne granice."

Servisi postoje — ali samo za zajedničke stvari u kernelu: ICurrentMember (ko je ulogovan), IAppText (prevodi), event bus, konverzija valuta. Modul ih koristi kroz interfejs, ne pravi svoje kopije.

06 Kompletan modul: Notes (bilješke)

Cijeli modul, fajl po fajl — šta je u svakom i za šta služi. Isti raspored ima svaki modul, pa kad razumiješ ovaj, razumiješ sve.

HomeOs.Modules.Notes
HomeOs.Modules.Notes.csproj
Definicija projekta. Referencira samo HomeOs.Platform — nijedan drugi modul. To je fizički dokaz izolacije: Notes ne može uvesti Finance ni da hoće. Uz to dodaje EF Core Design paket (za migracije).
NotesModule.cs ★
„Prijava na platformu". Registruje bazu, event-handlere, seeder i pretragu; sadrži NotesAppModule (manifest: id notes, ikona, boja, rute /notes i /api/notes, dozvole read/write:notes) i NotesHostModule koji host automatski pokupi pri pokretanju.
Domain/ Note.cs
Srce modula. Entitet bilješke. Privatni konstruktor + tvornička Create i metode Update/SetPinned. Ovdje su pravila: čisti razmake, max 12 tagova, SharedWith se puni samo kad je vidljivost Shared. Sva svojstva su private set — ne mogu se prepraviti spolja. Nosi i EntryDate (kad postoji → bilješka je dnevnički zapis).
Features/ NotesEndpoints.cs
API rute i njihova logika: GET / (lista), POST / (nova), PUT /{id} (izmjena), POST /{id}/pin (zakači), DELETE /{id}. Tu su i pomoćne funkcije za vidljivost i dozvole: VisibleQuery (grubi filter u bazi), CanSee (fina provjera), Editable (smije li mijenjati/brisati), ToDto (pretvori u izlazni oblik).
Features/ NoteDtos.cs
Oblici podataka koji putuju do/od frontenda: NoteDto (šta se vraća, uklj. CanEdit), SaveNoteRequest (unos za create/update) i PinNoteRequest. DTO ≠ domenski model — namjerno, da baza i API mogu evoluirati odvojeno.
Persistence/ NotesDbContext.cs
Most prema MySQL-u. Mapira Note na tabelu Notes: primarni ključ, maksimalne dužine (naslov 200, sadržaj 8000), enum Visibility se čuva kao tekst, i indeks (household + pinned + updated) za brzo listanje.
Persistence/ NotesDbContextFactory.cs
Pomoćna „design-time" tvornica da alat dotnet ef može praviti migracije bez pokretanja cijele aplikacije. Čisto razvojni alat.
Persistence/ Migrations/
Auto-generisano. Istorija promjena šeme baze (npr. „dodano polje EntryDate"). Ne piše se ručno — generiše ga EF, a služi da se baza može ponovljivo nadograditi.
Contracts/ NoteEvents.cs
Javne „poruke" modula — NoteCreated događaj koji se objavi na event bus kad nastane bilješka. Drugi mogu slušati, a da ne znaju ništa o Notes modulu.
Search/ NotesSearchProvider.cs
Utikač u globalnu pretragu — pretraži naslov/sadržaj, poštujući vidljivost, i vrati do 5 rezultata s linkom na /notes.
Seeding/ NotesDemoSeeder.cs
Samo za demo/razvoj — ubaci nekoliko primjera bilješki (Wi-Fi lozinka, recept…) u „Demo Home" domaćinstvo, i to samo ako je demo režim uključen i ako bilješki još nema.

Vidljivost bilješke je Private / Household / Shared. Logika u NotesEndpoints poštuje to: autor vidi svoje, svi vide Household, kod Shared samo izabrani članovi (SharedWith), a „manager" (Owner/Admin) vidi sve osim tuđih privatnih. Isti obrazac dozvola dijele svi moduli kroz platformu.

07 Frontend: platform, shared, apps

Tri foldera s jasnom podjelom uloga. Pravilo: apps smiju koristiti platform i shared — ali nikad jedna aplikacija drugu.

platform/ — jezgra (kernel) na klijentu

„Mozak" frontenda: sposobnosti koje aplikacije koriste, a ne prave same — podaci, prijava, real-time, registri. Nije UI.

FolderZa šta služi
api/Centralni HTTP klijent — api.get/post/put/del i ApiError. Svaki poziv prema backendu ide kroz ovo.
apps/Klijentski registar aplikacija — povuče manifeste sa backenda, i useApps() iz njih gradi navigaciju i rute. Parnjak backendovom IAppModule.
auth/Prijava/odjava i trenutni korisnik (useAuth) + tipovi.
query/Konfiguracija TanStack Query klijenta (keš, retry politika).
notifications/Notifikacije + SignalR real-time klijent (useRealtime) — žive poruke i obavijesti.
search/Poziv globalne pretrage koju moduli pune (vidi NotesSearchProvider).
i18n/Prevodi (react-i18next) — locales/en.json, bs.json. Bosanski + engleski.
money/Formatiranje i konverzija novca (formatMoney).
members/ · households/ · links/ · attachments/ · audit/Pristup zajedničkim platformskim stvarima: članovi, domaćinstva, veze entiteta, prilozi, dnevnik promjena.
surfaces/Tačke proširenja — npr. dashboardWidgets gdje aplikacije ubacuju svoje widgete na dashboard.
ui/Zustand store-ovi za UI stanje: toastovi, potvrde (confirm), zvuk, opšte stanje sučelja.

shared/ — zajedničke UI cigle

„Glupe", reupotrebljive komponente i stilovi — bez poslovne logike. Svaka aplikacija ih slaže po svom.

ŠtaSadržaj
components/Modal, Avatar, Attachments, LinkedItems, Toaster, ConfirmHost, ErrorBoundary (hvata greške u UI-u), GlobalLoadingBar, Req (oznaka obaveznog polja).
styles/tokens.css — dizajn tokeni (boje, razmaci, module-boje); ui.css — zajedničke klase. Jedno mjesto za izgled cijele aplikacije.

apps/ — same aplikacije

Po jedan folder za svaku aplikaciju (finance, notes, tasks, calendar…). Ogledalo backend modula. Svaka ima svoj ekran, hookove i API sloj, a sve zajedničko uvozi iz platform/ i shared/.

„platform je kernel — sposobnosti (podaci, prijava, real-time, registri). shared su reupotrebljive UI komponente i stilovi. apps su same aplikacije. Aplikacije koriste prva dva, ali nikad jedna drugu — isto pravilo kao na backendu."

09 Šta je dobit

→

Otvoreno za proširenje, zatvoreno za izmjenu. Nova aplikacija ne zahtijeva promjenu postojeće — manji rizik od kvarova.

→

Brži razvoj i lakši onboarding. Ista mentalna slika na backendu i frontendu; svaki modul je zaokružen i predvidiv.

→

Tačno ono što zadatak traži. Proširivost je srž zadatka, a ne naknadna misao — arhitektura je izvedena iz tog zahtjeva.
